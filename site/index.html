Projects

caro.md

caro.md imports cars to Moldova from Korea, China and the USA, and it is in production. I build its Next.js web app; a Django admin and API sit behind it.

The hard part is the Korean catalog: 9,000+ cars read live from the source marketplace through a pool of proxy exits, with Redis caching and a stale copy served when the source fails.

A calculator turns a car on another continent into a turnkey price: car price, auction fees, shipping and Moldovan customs from the official customs API, in USD, EUR and MDL at live rates.

  • The design lives in one Pencil file with every page and reusable component. The agent edits it through Pencil's MCP server and checks each change on a rendered screenshot.
  • Playwright end-to-end tests cover the calculator, the request forms, both languages and ad attribution, against a mock backend.
  • Every fix gets a short patch note (problem, root cause, solution, prevention), and the notes are folded into the rules the implementing agent reads, so a mistake is not repeated.

Leads come in through the site.

infodreamhome.com

infodreamhome.com is the production website of a licensed Las Vegas general contractor, live since October 2026. I built most of it.

The hard part was a photo-heavy site that stays fast on a phone. Every route is prerendered, and photos are served as AVIF or WebP at the device's width, the main image first. On the key pages, Lighthouse mobile scores 100 for accessibility and 90+ for performance, out of 100.

  • The site was designed with Open Design. Later pages, such as the 404 and the navigation, were designed the same way inside the site's own design language.
  • Its late work went through OpenSpec changes. The quote form, SEO, image delivery, security headers and accessibility are written as specs with scenarios.
  • All copy lives in typed per-block content modules whose IDs match the blocks on the page, so the client's text edits land in one place.

Quote requests pass one validation module shared by the form and its handler, and land in the owner's inbox through Resend, with silent bot filtering. Leads come in through the site.

A multi-agent harness on Claude Code

Each roadmap step gets an orchestrator that leads an architect, a designer, a tester, an implementer and a fresh verifier from plan to pull request. The tester writes tests from the spec without reading the code, and the implementer never edits them.

I start a step with one line, answer only the decisions the agents cannot ground, and approve the merge on GitHub; a chat message or a PR comment does not count.

It is my own tool, used daily on my repositories and my three-person studio's. A Telegram chat files steps through an MCP server I wrote; the chat agent is tested on the live model against prompt injection.

What went wrong

  • One agent per step re-paid everything it read on every call and tested its own code, so I split it into roles.
  • An agent tried to approve its own pull request; the bot now has its own GitHub App identity.

What I measured

  • Verifier: as the only check it changed none of 74 steps; after the split into roles, 14 of 46.
  • MCP: the same headless call cost 135,948 tokens with every server loaded, 6,344 with --strict-mcp-config.
  • Pay in job posts: asked for dollars, a model guessed 90 roubles per dollar against the central bank's 82.51, so it now copies pay as written and code converts it.

Limits

A hook keeps unattended sessions writing only inside the project, but it covers file tools only; role order and pre-merge checks are a model following a written skill, with the merge pinned by --match-head-commit.
