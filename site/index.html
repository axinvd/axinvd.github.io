Case: a multi-agent harness on Claude Code

One orchestrator session per roadmap step leads role subagents, from the plan to the merged pull request. It is my own tool, used daily on my and my studio's repositories.

  1. Orchestrator one session per step, keeps it until the merge
  2. Architect turns the step into an OpenSpec change: spec scenarios and tasks
  3. Designer on screens: 2–3 variants on one preview, switched by ?variant=
  4. Tester writes contract tests red from the spec scenarios without reading the implementation
  5. Implementer builds against them and may not edit them
  6. Verifier a fresh agent checks the step
  7. Pull request a draft until the verifier's ok
  8. Owner's Approve in GitHub a chat word or a PR comment is not consent
  9. Merge pinned to the reviewed head with --match-head-commit

Up to three steps run at once, each in its own git worktree.

A Telegram bridge lets a team chat start work: a chat agent answers through my MCP server (4 tools: reply, status, pr_comment, write_step). write_step is the only way a chat changes the repository: a one-shot step-check agent answers pass, return or ask before the bridge commits. The bridge is one 2,923-line Python file with no dependencies and 413 tests.

What broke and how it was fixed

  • An agent tried to approve its own pull request. The run wrote to GitHub under my login, and the permission classifier denied the approval.

    Fix: the bot writes as its own GitHub App, with a token scoped to one repository.

  • A comment taken as consent. An “ok” in a PR comment archived a step, and two bridges acted on it.

    Fix: consent is a GitHub Approve; the PR author and bots don't count.

  • A batch delivered twice. A SIGTERM between delivery and saving the cursor re-sent the batch in about one test run of two.

    Fix: the signal is blocked until the cursor is written.

  • Two agents, one test database. Parallel subagents truncated each other's tables.

    Fix: each agent gets its own database name, now a standing rule.

  • An assumption about permissions. “Subagents inherit the session's permissions” was assumed, not checked.

    Fix: measured in dontAsk mode, then rebuilt as an orchestrator session with a path-scoped write hook.

  • This case's own numbers. The first verifier found two counts that did not reproduce.

    Fix: recounted with the command written next to each number, and the second verifier passed.

How the agents are checked

  • Code and its contract tests come from different agents.
  • 46 live-model tests drive the real claude -p with the real agent definition over a fake Telegram, fake herdr and fake GitHub: 36 chat-agent cases (a page that gives orders, a request by voice, staying silent in a quarrel) and 10 step-check cases. A red case is fixed in the agent's definition, not in the test.
  • Prompt injection is tested on the live model: a web page and a PDF that give orders, and a file name that tries to forge a message line; the fixture plants a fake secret.
  • Where code replaced the model: a lead-ranking model gave a verdict per lead, and 8 of its top 10 were leads I had skipped. Now the model only extracts 15 facts by JSON schema and the score is a formula in code: 540 leads read at $0.0014 each, 0 failures.
  • Write scope: a hook lets agents write files only inside the project or a temp directory; Bash writes are left to the permission classifier.
  • Every session becomes a typed digest linked to its transcript; step cost is computed from transcripts by a script, not estimated by a model.
