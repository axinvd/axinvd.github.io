Case: a multi-agent harness on Claude Code

I ship software through a multi-agent harness I built on Claude Code. One orchestrator session per roadmap step leads an architect, a designer, a tester, an implementer and a fresh verifier, from the plan to the merged pull request.

Nothing merges until I approve it on GitHub; a chat message or a PR comment does not count as approval.

The tester writes the tests from the spec without reading the code, and the implementer may not edit them.

121 roadmap steps have run through it, with the cost of every role measured. It is my own tool, used daily on my and my studio's repositories.

  1. Orchestrator one session per step, keeps it until the merge
  2. Architect turns the step into spec scenarios and tasks
  3. Designer on screens: 2–3 variants on one preview
  4. Tester tests from the spec, without the code
  5. Implementer builds against them, may not edit them
  6. Verifier a fresh agent checks the step
  7. Pull request a draft until the verifier's ok
  8. Owner's Approve in GitHub
  9. Merge pinned to the reviewed head

Up to three steps run at once, each in its own git worktree.

tg-flow lets my studio start work from a Telegram chat. The chat agent has four tools through an MCP server I wrote. The only one that changes the repository, write_step, first passes a one-shot check agent that answers pass, return or ask. The bot acts on GitHub as its own app, never as me.

The hardest problems, and what I changed

  • One agent per step did not scale. It peaked at 130–681k tokens of context, paid again for everything it had read on each of 100–180 apply calls, and wrote the tests for its own code. I split it into roles. A replay of real calls predicted peak context per agent at 0.54 of the single agent's, and total input at 0.42. That is a simulation, and I treat it as optimistic.
  • An agent tried to approve its own pull request: the run wrote to GitHub under my login, and the permission classifier denied the approval. Now the bot acts as its own GitHub App, with a token scoped to one repository.
  • An “ok” in a PR comment archived a step, and two bridges acted on it. Now consent is a GitHub Approve, and the PR author and bots do not count.
  • The figures of this very case failed their first verifier: two counts did not reproduce. I recounted them with the command written next to each figure, and the second verifier passed.

What I measured

  • The verifier, before and after the split. When one agent built each step and a single verifier was the only check, the verifier changed none of 74 steps. Once the roles were split, it found something on 17 and changed 14 of 46 steps.
  • MCP schemas. The same headless call that answers “ok” cost 135,948 tokens with every MCP server loaded, and 6,344 with --strict-mcp-config: 21 times fewer. The flag now goes on every script call, and a test guards it.
  • Where code replaced a model. A model that ranked job leads by verdict put 8 of its top 10 among leads I had skipped myself. Now the model only extracts 15 facts by JSON schema, and a formula in code does the scoring.

How the agents are checked

  • The chat agent and the step check are tested on the live model, against prompt injection too: the real claude -p with the real agent definition, over a fake Telegram, a fake herdr and a fake GitHub. Among the cases are a web page and a PDF that give orders, a file name that tries to forge a message line, a request by voice, and staying silent in a quarrel. A red case is fixed in the agent's definition, not in the test.
  • Every session becomes a typed digest linked to its transcript. The cost of a step is computed from transcripts by a script, not estimated by a model.

Limits

The write hook covers file tools only; writes through the shell are left to the permission classifier. Role order and pre-merge checks are held by a model following a written skill, with the merge pinned to the reviewed head by --match-head-commit. That is a documented trade-off, not code.

caro.md

caro.md imports cars to Moldova from Korea, China and the USA, and it is in production. I build its web app.

The hard part is the Korean catalog: 9,000+ cars read live from the source marketplace through a pool of proxy exits, with Redis caching and a stale copy served when the source fails.

A calculator turns a car on another continent into a turnkey price: car price, auction fees, shipping and Moldovan customs from the official customs API, in USD, EUR and MDL at live rates.

Case pages with photo galleries are seeded from the client's documents by a parsing script. Playwright end-to-end tests and Sentry stand behind the site.

The design was made with AI in Pencil, and the site was built with Claude Code. Leads come in through the site.

infodreamhome.com

infodreamhome.com is the production website of a licensed Las Vegas general contractor, live since October 2026. I built most of it.

The hard part was a photo-heavy site that stays fast on a phone. Every route is prerendered, and photos are served as AVIF or WebP at the device's width, the main image first. On the key pages, Lighthouse mobile scores 100 for accessibility and 90+ for performance, out of 100.

Copy lives in typed per-block content modules. Quote requests land in the owner's inbox through Resend, with field-level validation and silent bot filtering. Each page has a canonical URL and a link preview, and JSON-LD (GeneralContractor, FAQPage, breadcrumbs) and a sitemap tell search engines about the business.

The design was made with AI in Open Design, and the site was built with Claude Code; its late work ran as OpenSpec changes. Leads come in through the site.

Next.js 16 App Router, Bun in Docker

Both sites were built with Claude Code before the harness existed; it appeared on 3 November 2026.
